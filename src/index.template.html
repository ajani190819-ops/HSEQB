Help & Tutorial

Getting Started

Open the sidebar and work through each section in order: Session → Players → Teams → Categories. Once configured, use the Record Answer panel to log answers in real time. All data syncs automatically across connected devices via Firebase.

Sessions

Each match is a Session. Create one with a descriptive name before recording answers. Use Load Session to switch between matches. Sessions can be excluded from analytics — excluded sessions are dimmed and ignored in all Stats calculations.

Players & Teams

Add players in the Players section, then create teams in Teams and assign players to them. Only players assigned to a team are selectable when recording answers. Players are stored globally and available across all sessions.

Recording Answers

Select a Player, then a Point Type, then a Category (optional for Neg), then press Record Answer. Use the answer log to delete mistakes.

Toss-Ups Heard Counter

Tracks how many toss-up questions have been read. It increments once on the first outcome for each toss-up; a correct answer after a Neg or Miss is treated as a follow-up to that same question. Use the +/− buttons to correct it manually. Required for normalized player metrics.

Stats (Analytics)

Toggle to the Stats view using the switch in the header. Stats are aggregated across all non-excluded sessions and organized into four tabs:

  • Overview — totals, category breakdowns, top performers
  • Players — ranked leaderboard; expand for metrics or click name for detail
  • Charts — visual breakdown of answer types, categories, and trends
  • Team Compositions — per-team stats per session

Player Metrics

Player analytics use official toss-up decisions only. Bonuses remain team-scored and are never assigned to an individual player.

  • Total Points — individual toss-up points: +15 per power, +10 per regular toss-up, and −5 per neg
  • Toss-Ups Heard — opportunity count used to compare players with different amounts of playing time
  • Raw TU/20 — net toss-up points at a common pace of 20 toss-ups: (15P + 10T − 5N) / H × 20
  • Leaderboard Score — the leaderboard score; earned after one full session (20 toss-ups heard), with limited samples gently moved toward the team average using confidence
  • Reliability — correct decisions divided by all recorded decisions: (P+T) / (P+T+N+M) × 100
  • Power Rate — powers divided by all recorded decisions: P / (P+T+N+M) × 100. Negs and misses count against this rate.
  • TU/20 — participation pace: (P+T+N+M) / H × 20
  • Confidence — sample-size weight: H / (H+k). At H=k, the raw score is 50% trusted.

Official Score System

The player leaderboard uses Leaderboard Score as its only overall score. A player earns it after hearing at least 20 toss-ups (one full session); limited samples are then shrunk toward the team average. This avoids double-counting related measures such as buzz rate, reliability, and conversion.

Leaderboard Score = Confidence × Raw TU/20 + (1 − Confidence) × Team Average

Bonuses are shown in team totals and the answer log, but are not used for individual player rankings because bonus conversion is shared by the team.

Leaderboard Sorting

Sort by Total Points, Leaderboard Score, Reliability, Power Rate, TU/20, or A–Z. Ties are broken by the official toss-up counts, then fewest Negs.

Export & Import

Export to CSV for spreadsheets or JSON to back up and re-import a full session. Both options are in the Data section of the sidebar.

What Syncs Globally

Stored in Firebase and synced instantly across all connected devices:

  • All session data (answers, scores, toss-ups heard)
  • Global player pool
  • Skill score settings and low-data overrides
  • App version, release history, and update info

Stored with your Firebase account and cached locally: theme mode, accent color, scrollbar visibility, and sidebar state.

Version Badge & Deploy Indicator

The version badge in the header shows the current file version. When viewed on the live GitHub Pages site, its border changes color to reflect the latest deploy status — green = deployed successfully, yellow pulsing = deploy in progress, red = deploy failed. If a new deploy completes while you have the page open, a banner will appear prompting you to refresh.

Updates & Changelog

Open Updates in the header to see the shared release history and the latest public changelog. If you are running a local copy and a newer version has been published, you can download it there or from the update banner — admins can attach the new index.html to Firebase, so the download works without a GitHub request on restricted school networks. Admins also use this center to publish builds and write the release log.

Visual Settings

Choose Light, Dark, or Device theme, change the Accent Color, or hide scrollbars in the Visual Settings section of the sidebar.
